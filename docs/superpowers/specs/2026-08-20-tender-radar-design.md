# Tender Radar — аналіз ризиків публічних закупівель Харківської області

**Дата:** 2026-08-20
**Статус:** дизайн затверджено, готовий до планування реалізації

## 1. Задача

Сервіс, який знаходить ознаки завищення цін та інших порушень у публічних закупівлях
Харківської області (з окремим фокусом на закупівлі філій АТ «Українська залізниця»),
і по кожній знахідці збирає досьє: хто замовник, хто переможець, хто засновники
переможця, де ще ця фірма вигравала по Україні і що там спрацьовувало.

Первинний користувач — юрист, слідчий, аудитор, журналіст-розслідувач.

### Що система робить і чого не робить

Система видає **індикатори ризику, що потребують перевірки**. Вона не встановлює факт
злочину і не називає конкретну особу чи компанію злочинцем. Кожна знахідка показує
арифметику, з якої вона отримана, і посилання на першоджерело.

## 2. Результати дослідження джерел даних

Усі endpoint нижче перевірені живими запитами 2026-08-20.

### 2.1 Державна система ризик-індикаторів — `risks.prozorro.gov.ua`

Офіційна система, наказ Мінфіну № 476 від 27.09.2024, інтегрована в кабінет
Держаудитслужби. API відкритий, без авторизації.

| Endpoint | Що дає |
|---|---|
| `GET /api/filter-values` | 14 діючих індикаторів (`ari-1-1`, `ari-1-2`, `sas24-3-1`…`sas24-3-15`) + список регіонів |
| `GET /api/risks?skip=N&edrpou=&tender_id=&risks=&risks_all=&sort=&order=` | 36 978 тендерів зі спрацюваннями, по 20 на сторінку |
| `GET /api/risks-report?risks=<id>&risks_all=false` | CSV-вивантаження |

Структура запису: `_id`, `dateAssessed`, `procuringEntity` (з `address.region` та
`identifier.id` = ЄДРПОУ), `risks` — словник `risk_id → {name, description,
legitimateness}`. Поле `legitimateness` містить точну статтю закону.

CSV містить колонки: `_id, tenderID, dateAssessed, dateModified,
procuringEntityRegion, procuringEntityEDRPOU, procuringEntityName, valueAmount,
valueCurrency, worked_risks`.

**Виміряно по Харківській області:** 2 165 тендерів зі спрацюваннями на 52,8 млрд грн.
Це нижня межа: цифра отримана з 5 індикаторів із 14 (`ari-1-1`, `ari-1-2`,
`sas24-3-2`, `sas24-3-9`, `sas24-3-13`), що дали 31 136 унікальних тендерів по
Україні. Повне вивантаження всіх 14 індикаторів дасть більше.

**Обмеження:** параметр `region` на сервері не працює — повертає 0 для будь-якого
регіону. Фільтри `edrpou` і `tender_id` працюють. Тому регіон фільтруємо локально
за колонкою `procuringEntityRegion` з CSV.

**Обмеження:** вивантаження CSV без фільтра `risks` обривається. Тому качаємо
по одному індикатору — 14 запитів покривають усе.

### 2.2 Модуль моніторингу Держаудитслужби — `audit-api.prozorro.gov.ua`

`GET /api/2.5/monitorings` — хронологічна стрічка, `GET /api/2.5/monitorings/{id}` —
картка. Поля: `status`, `tender_id`, `decision` (наказ про початок моніторингу
повним текстом), `reasons`, `conclusion` (для завершених — з `violationType`),
`posts`, `parties`.

Дає межу між підозрою і встановленим фактом.

**Обмеження:** `conclusion.violationType` у вибірці майже завжди `other` — структурне
поле малоінформативне, змістовна інформація в тексті `description`.

### 2.3 Електронний каталог — `market-api.prozorro.gov.ua`

`GET /api/products` та `GET /api/products/{id}` — товар із `title`, `classification`
(ДК021 = CPV), `relatedCategory`, `images`, `description`.
`GET /api/offers` та `GET /api/offers/{id}` — пропозиція з `value.amount`,
`relatedProduct`, `suppliers`, `status`.

Це офіційний державний довідник цін на стандартні товари. Замінює скрейпінг роздрібу
як основне джерело еталонної ціни.

### 2.4 Основний API закупівель — `public.api.openprocurement.org`

`GET /api/2.5/tenders` — хронологічна стрічка за `dateModified`.
`GET /api/2.5/tenders/{id}` — повна картка: `items` (з `quantity`, `unit`,
`classification`), `lots`, `bids`, `awards`, `contracts`, `procuringEntity`, `value`.

**Виміряна економіка:** за 2026-08-20 у стрічці понад 8 000 подій змін.
Харківська область — близько 4 % потоку.

`opt_fields` повертає `procuringEntity` (а отже й регіон), але **не повертає**
`items`, `value`, `awards`. Тому ingest двоступеневий: дешеве сканування стрічки
по 100 записів для відбору за регіоном, повна картка — тільки для відібраного.
Для Харківської області це ~600–1000 тендерів на добу.

**Масових дампів бази тендерів не існує** — лише API.

### 2.5 ЄДР — `data.gov.ua`

Набір `a1799820-195b-4982-8141-6e84f58103e7`. Ресурс `UO.zip` — 326 858 701 байт,
оновлений 2026-08-18. Містить перелік засновників та кінцевих бенефіціарних власників
юридичних осіб. Безкоштовно. Адреси засновників приховані через воєнний стан.

Доступ до ЄДР у формі відкритих даних відновлено 19.01.2026.

Платні YouControl / Opendatabot не потрібні.

### 2.6 Що перевірено і не працює

`prozorro.gov.ua/api/search/tenders` мовчки ігнорує `region`, `cpv`, `edrpou`,
`classification_id`; параметр `text` завжди повертає 0. Розбір фронтенд-бандла сайту
показав, що справжній пошуковий запит лежить у lazy-чанку, якого немає в основному
коді. Висновок: на цей API не спиратися, будувати власний індекс.

## 3. Три рівні достовірності

Центральний принцип точності: нижчий рівень ніколи не подається як вищий.

| Рівень | Джерело | Формулювання в UI |
|---|---|---|
| **Підтверджено** | Висновок моніторингу ДАСУ | «Держаудитслужба провела моніторинг і встановила порушення» |
| **Офіційний індикатор** | risks.prozorro.gov.ua | «Спрацював державний індикатор `ari-1-1`» + текст статті закону |
| **Власний аналіз** | Наші детектори | «Ціна за одиницю вища за каталожну в N разів — потребує перевірки» |

Кожна знахідка в UI має бейдж рівня і посилання на першоджерело.

## 4. Архітектура

Три шари, розділені начисто. Ingest і Analysis не знають про UI; UI не ходить у
зовнішні API.

### Ingest (Vercel Cron)

| Воркер | Періодичність | Що робить |
|---|---|---|
| `risks` | щодня | 14 CSV з `risks-report`, фільтр за регіоном, upsert у `risk_flags` |
| `tenders` | щогодини | сканування стрічки з `opt_fields`, відбір за регіоном/ЄДРПОУ, повна картка для відібраного |
| `monitorings` | щодня | стрічка audit-api, картки для тендерів, що вже є в базі |
| `market` | щотижня | products + offers → `catalog_prices` |
| `edr` | щомісяця | UO.zip → засновники та бенефіціари для ЄДРПОУ, що є в базі |

Кожен воркер тримає курсор у таблиці `ingest_cursors` — процес відновлюваний,
падіння не втрачає даних.

### Analysis

Перерахунок `price_benchmarks` і прогін власних детекторів. Усе детерміноване:
цифри рахує код, не модель. Результат — рядки в `findings` зі збереженою
доказовою базою в `evidence jsonb`.

### Web — Next.js App Router, українська мова

- `/` — стрічка знахідок Харківської області з фільтрами: рівень достовірності, індикатор, замовник, сума, дата
- `/tender/[tenderID]` — картка тендера: позиції з ціною за одиницю, порівняння з каталогом і медіаною, спрацьовані індикатори зі статтями, моніторинги, учасники, переможець
- `/supplier/[edrpou]` — досьє постачальника: засновники, бенефіціари, дата реєстрації, усі перемоги по Україні, усі знахідки, пов'язані компанії через спільних засновників
- `/entity/[edrpou]` — досьє замовника, симетрично
- `/search` — єдина точка входу: ЄДРПОУ, номер тендера або назва товару

## 5. Модель даних (Supabase / Postgres)

```
tenders            id, tender_id, title, description, status, method,
                   value_amount, currency, date, entity_edrpou, entity_name,
                   region, locality, raw jsonb
tender_items       tender_id, description, cpv_code, cpv_name, quantity,
                   unit_code, unit_name, unit_price, lot_id
bids               tender_id, supplier_edrpou, supplier_name, amount, status
awards             tender_id, supplier_edrpou, supplier_name, amount, status, date
contracts          tender_id, amount, signed_at, amendments jsonb
risk_flags         tender_id, risk_id, risk_name, description, legitimateness,
                   date_assessed
monitorings        monitoring_id, tender_id, status, reasons jsonb,
                   decision_text, conclusion jsonb, dates
suppliers          edrpou PK, name, registered_at, founders jsonb,
                   beneficiaries jsonb, first_seen
catalog_prices     product_id, title, cpv_code, offer_price, currency,
                   supplier, fetched_at
price_benchmarks   cpv_code, unit_code, n_samples, median, p25, p75, updated_at
findings           tender_id, tier, detector_key, severity, score, title,
                   explanation, evidence jsonb, created_at
ingest_cursors     worker, cursor, updated_at
```

Сирий JSON тендера зберігається цілком у `tenders.raw` — щоб додавання нового
детектора не вимагало перекачування.

## 6. Власні детектори (рівень 3)

| Ключ | Що ловить | Поріг |
|---|---|---|
| `catalog_gap` | Ціна за одиницю проти ціни того ж CPV у Prozorro Market | ≥1 зіставлена позиція каталогу |
| `price_overrun` | Ціна за одиницю проти медіани по CPV | вибірка ≥10 |
| `single_bidder` | Один учасник на великій конкурентній процедурі | — |
| `threshold_split` | Дроблення закупівлі нижче порогу відкритих торгів | той самий замовник + CPV + вікно |
| `cosmetic_discount` | Перемога зі знижкою <1 % від очікуваної вартості | — |
| `new_supplier_big_win` | Нещодавно зареєстрована фірма бере великий контракт | дата з ЄДР |
| `repeat_pair` | Систематичні перемоги однієї зв'язки замовник↔постачальник | концентрація |
| `contract_inflation` | Сума договору зросла допугодами вище ціни перемоги | — |

Кожна знахідка зберігає числа, з яких порахована, щоб UI показав арифметику.

## 7. Довідник статей

Статична таблиця «тип порушення → статті ККУ, що зазвичай застосовуються»
(191, 364, 366 та інші). Виводиться з міткою «можлива кваліфікація, потребує
перевірки», ніколи як твердження. Це довідка для юриста, а не висновок системи.

## 8. Етапи

**Етап 1 — запуск із наповненою базою.**
Ingest `risks`, `tenders` (Харківська область + філії УЗ), `monitorings`, `market`,
`edr`. Детектор `catalog_gap`. Сторінки: стрічка, тендер, постачальник, замовник,
пошук. Рівні 1 і 2 працюють повністю, рівень 3 — у частині каталогу.

День запуску: щонайменше 2 165 реальних знахідок зі статтями закону.

**Етап 2 — власна аналітика.**
Фоновий збір національного корпусу для `price_benchmarks`, решта детекторів,
зв'язки компаній через спільних засновників.

**Етап 3 — судові рішення.**
Єдиний державний реєстр судових рішень. Винесено в окремий етап через жорсткі
ліміти — включення його в перший запуск завалило б запуск.

## 9. Свідомі обмеження

- **Довідник медіанних цін наповнюється поступово.** Масових дампів немає, корпус
  накопичується зі стрічки. У перші дні детектори з порогом вибірки не спрацьовують.
  Це не баг, це ціна чесного порога.
- **Каталог Prozorro Market покриває стандартні товари.** По рейках, шпалах,
  ремонтних роботах каталожної ціни не існує — там працює лише медіана.
- **Скрейпінг роздрібу** (Rozetka, Hotline) — необов'язковий третій шар, не входить
  до етапу 1.
- **Без `ANTHROPIC_API_KEY`** пояснення знахідок формуються за шаблонами з
  підставленими числами. Місце під Claude передбачене: з'явиться ключ — вмикається
  змінною середовища, переписувати нічого не доведеться.
- **Адреси засновників** закриті воєнним станом і в системі відсутні.

## 10. Стек

Next.js (App Router) + Supabase (Postgres) + Vercel. Ingest-воркери — Vercel Cron.
Інтерфейс українською.
