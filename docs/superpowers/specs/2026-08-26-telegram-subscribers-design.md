# Telegram: рассылка всем подписчикам

## Задача

Бот шлёт ежедневный дайджест в один чат — тот, что задан в `TELEGRAM_CHAT_ID`.
Нажатие «Запустить» не даёт ничего: обработчика `/start` нет, вебхука нет,
списка подписчиков нет. Надо, чтобы дайджест получал каждый, кто подписался.

Бот публичный: подписаться может любой, без модерации и кодов. Все получают
один и тот же текст — никаких персональных фильтров.

## Решение в трёх частях

### 1. Хранилище — Supabase

Проект `tender_radar_bot` (ref `ysaclorvgikqlbiuhxtt`, eu-west-1), таблица:

```sql
create table public.tg_subscribers (
  chat_id         bigint primary key,
  created_at      timestamptz not null default now(),
  unsubscribed_at timestamptz
);

create index tg_subscribers_active_idx
  on public.tg_subscribers (chat_id)
  where unsubscribed_at is null;

alter table public.tg_subscribers enable row level security;
```

Отписка мягкая: `/stop` проставляет `unsubscribed_at`, `/start` его обнуляет.
Так повторная подписка не плодит дублей, а уход человека видно в данных.

RLS включён, политик нет намеренно: anon-ключ не должен видеть ничего.
Вебхук и джоб ходят под service-ключом, который RLS обходит.

Новый модуль `src/store/subscribers.ts` — `add`, `remove`, `listActive`.
Ходит в PostgREST обычным `fetch`, **без `@supabase/supabase-js`**: у проекта
сейчас ноль runtime-зависимостей, и ради трёх запросов ломать это не стоит.
Нет ключей в окружении — модуль возвращает `null`, вызывающий пропускает шаг.
Тот же приём, что в `loadTelegramConfig()`.

Переменные: `SUPABASE_URL`, `SUPABASE_SERVICE_KEY` — в GitHub Secrets (джоб)
и в Vercel env (вебхук).

### 2. Вебхук

Маршрут `POST /telegram/webhook` в `server/router.ts`, зарегистрированный в
начале `handle()` — **до** `loadAuthConfig()`. Иначе Google-гейт вернёт
Telegram страницу логина и апдейты потеряются.

Подлинность — через механизм Telegram: `secret_token` задаётся при
`setWebhook` и приходит в заголовке `X-Telegram-Bot-Api-Secret-Token`.
Не совпал — 401, тело не парсим. Без этого эндпоинт открыт всем, и в базу
можно накидать фальшивых подписчиков. Переменная: `TELEGRAM_WEBHOOK_SECRET`.

Требует правки типа `HttpRequest`: добавить `headers` (сейчас только
`cookieHeader`, `method`, `body`). Затрагивает `api-src/handler.ts` и
`server/serve.ts`.

Поведение: `/start` → upsert и приветствие. `/stop` → пометить отписавшимся и
подтвердить. Остальное — игнорировать.

**Отвечаем 200 всегда**, даже при внутренней ошибке. На не-200 Telegram
ретраит по нарастающей и в итоге отключает вебхук.

### 3. Рассылка

`scripts/daily.ts`, шаг 5: текст строится один раз (он у всех одинаковый),
дальше цикл по `listActive()`.

- **Пауза 40 мс** между отправками. Лимит Telegram — около 30 сообщений в
  секунду, 40 мс дают 25 с запасом.
- **403 → отписка.** Заблокировал бота или удалил чат — помечаем
  `unsubscribed_at`, иначе список копит мертвецов.
- **429 → ждём `retry_after` и повторяем один раз.** Не помогло — считаем
  ошибкой и идём дальше: один чат не должен валить рассылку остальным.
- **Сводка админу** в `TELEGRAM_CHAT_ID`: доставлено / отписалось / ошибок.
  Без неё поломку никто не заметит — люди просто перестанут получать письма.

Supabase не настроен — поведение как сейчас: дайджест уходит только админу.
Проект должен продолжать запускаться на машине без настройки.

## Тесты

Расширяем `tests/telegram.test.ts`:

- разбор апдейта: `/start`, `/stop`, мусор, отсутствие `message`;
- проверка `secret_token`: совпал / не совпал / отсутствует;
- классификация ответов: 403 → отписка, 429 → один повтор, 200 → доставлено;
- `buildMessage` не трогаем, он уже покрыт.

## Разовая настройка

После деплоя — один вызов `setWebhook` с `secret_token`, вручную.

## Что осознанно не делаем

- Фильтры по региону и сумме — общий дайджест всем.
- Модерацию подписчиков — бот публичный.
- Библиотеку Supabase — хватает `fetch`.
